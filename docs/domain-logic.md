# Domain logic

This document is the audit's reference for the domain rules the Goat It API (`goat-it-api`) enforces. It covers the pure domain of the two bounded contexts — `question` (`file:src/contexts/question/domain/`) and `question-theme` (`file:src/contexts/question-theme/domain/`) — plus the shared kernel rules both depend on (`file:src/shared/domain/`): entity and value-object shapes, invariant policies, deduplication logic, repository contracts and domain error classes. Values are quoted from the constants and rules files they are defined in. Domain code is pure and deterministic by rule (`file:docs/architecture.md` §3.4, §4.1): validation happens at the Zod boundary, while the domain policies (`ensure*` predicates) enforce invariants. Every claim cites the repository file it is based on.

## Question invariants

### Types, categories and difficulties

- A question is a free-text quiz item: `statement` + `answer` + optional `context`/`trivia`, one of 4 categories, one of 3 cognitive difficulties, one of 4 statuses (`file:src/contexts/question/domain/types/question.entities.ts`, `file:src/contexts/question/domain/types/question.value-objects.ts`).
- There are no multiple-choice / true-false / simple question types; nothing in the entities or constants models answer options.
- Categories: `trivia`, `lexicon`, `riddle`, `explanation` — `QUESTION_CATEGORIES` in `file:src/contexts/question/domain/constants/question.constants.ts`.
- Cognitive difficulties: `easy`, `medium`, `hard` — `QUESTION_COGNITIVE_DIFFICULTIES` (same file). The semantic sort order is `easy → medium → hard` (`QUESTION_COGNITIVE_DIFFICULTY_SORT_ORDER`, same file).
- Author roles: `admin`, `game`, `ai`; creation allows only `admin` and `ai` (`QUESTION_AUTHOR_ROLES`, `QUESTION_CREATION_AUTHOR_ROLES`, same file). The author display name is bounded to `QUESTION_AUTHOR_NAME_MIN_LENGTH = 3` .. `QUESTION_AUTHOR_NAME_MAX_LENGTH = 30` (same file), enforced in `file:src/contexts/question/application/dto/question-creation/question-author-creation/question-author-creation.dto.shape.ts`.
- Statuses: `pending`, `active`, `archived`, `rejected` (`QUESTION_STATUSES`, same file); the semantic sort order is `pending → active → rejected → archived` (`QUESTION_STATUS_SORT_ORDER`, same file). Rejection types: `inappropriate-content`, `incorrect-information`, `poor-quality`, `duplicate-question`, `other` (`QUESTION_REJECTION_TYPES`, same file).
- **Creation status is not client-controlled.** It is derived from the author role by `computeQuestionStatusFromAuthorRole` (`file:src/contexts/question/domain/rules/question.rules.ts`): `admin` → `active`, any other creation role (`ai`) → `pending`; the rule is applied by `createQuestionCreationCommandFromDto` in `file:src/contexts/question/application/mappers/question.mappers.ts` and typed as `QuestionCreationStatus = pending | active` (`QUESTION_CREATION_STATUSES`, same constants file).

### Answer correctness rules

The API does **not** validate answer correctness: the answer is stored free text (`file:src/contexts/question/domain/types/question.value-objects.ts` — `QuestionContent.answer`). Nothing in `question.rules.ts` or the DTO validators compares answers or defines a correct-answer discriminator. Correctness is a game-side (consumer) concern, not an API invariant.

### Content and metadata limits

- Localized content: `statement` and `answer` are mandatory, `context` and `trivia` optional (`QuestionContent` in `file:src/contexts/question/domain/types/question.value-objects.ts`; the Mongoose schema mirrors it in `file:src/contexts/question/infrastructure/persistence/mongoose/schemas/question-content/question-content.mongoose.schema.ts`).
- Per-locale text entries: 1..500 characters after trim; per-locale `trivia` arrays: 1..10 items; every `LocalizedText`/`LocalizedTexts` must have at least one locale value (`LOCALIZED_TEXT_ENTRY_MIN_LENGTH`, `LOCALIZED_TEXT_ENTRY_MAX_LENGTH`, `LOCALIZED_TEXTS_MIN_LENGTH`, `LOCALIZED_TEXTS_MAX_LENGTH`, `LOCALIZED_TEXT_EMPTY_ERROR_MESSAGE` in `file:src/shared/application/dto/zod/validators/localization/constants/localization.zod.validators.constants.ts`; schemas in `file:src/shared/application/dto/zod/validators/localization/localization.zod.validators.ts`).
- Source URLs: `QUESTION_SOURCE_URLS_MIN_ITEMS = 1` .. `QUESTION_SOURCE_URLS_MAX_ITEMS = 5`, each a valid URL, all unique (`file:src/contexts/question/domain/constants/question.constants.ts`; enforced by `zQuestionSourceUrls` in `file:src/contexts/question/application/dto/zod/validators/question.dto.zod.validators.ts`).
- `isAdultContent` is a required boolean on creation (`file:src/contexts/question/application/dto/question-creation/question-creation.dto.shape.ts`).

### Theme assignment rules

- A question holds `QUESTION_THEME_ASSIGNMENTS_MIN_ITEMS = 1` to `QUESTION_THEME_ASSIGNMENTS_MAX_ITEMS = 3` theme assignments, each `{ theme, isPrimary, isHint }` (`file:src/contexts/question/domain/constants/question.constants.ts`; `QuestionThemeAssignment` in `file:src/contexts/question/domain/types/question.value-objects.ts`).
- **Exactly one assignment must be primary** and theme IDs must be unique — `refine(hasExactlyOneByKey(themes, "isPrimary", true))` and `refine(areValuesUniqueByKey(themes, "themeId"))` in `file:src/contexts/question/application/dto/question-creation/question-creation.dto.shape.ts` (helpers in `file:src/shared/application/dto/zod/refinements/array/array.zod.refinements.ts`).
- Referenced themes must exist and must not be archived: `CreateQuestionUseCase.throwIfQuestionNotCreatable` loads the themes via the published `GetQuestionThemesByIdsOrThrowUseCase` and rejects with `ReferencedQuestionThemeArchivedError` when any is archived (`file:src/contexts/question/application/use-cases/create-question/create-question.use-case.ts`).
- Assigning a theme (`file:src/contexts/question/application/use-cases/question-theme-assignment/assign-theme-to-question/assign-theme-to-question.use-case.ts`): the theme must not already be assigned (`QuestionThemeAssignmentAlreadyExistsError`), the question must be below the 3-theme maximum (`ensureQuestionThemeAssignmentsLimit`, `QuestionMaximumThemesError`), and the theme must not be archived.
- Removing a theme (`file:src/contexts/question/application/use-cases/question-theme-assignment/remove-theme-from-question/remove-theme-from-question.use-case.ts`): the assignment must exist and must not be primary (`ensureQuestionThemeAssignmentIsRemovable` in `file:src/contexts/question/domain/rules/question.rules.ts`), and the question must keep at least 1 theme (`QuestionMinimumThemesError`).
- Modifying an assignment (`file:src/contexts/question/application/use-cases/question-theme-assignment/modify-question-theme-assignment/modify-question-theme-assignment.use-case.ts`): the assignment must exist. The modification contract only allows `isPrimary: true` (promotion, which demotes all others in the same request; two concurrent promotions can still race the one-primary invariant — #1271) and/or `isHint` — `QuestionThemeAssignmentModificationContract` in `file:src/contexts/question/domain/repositories/question.repository-contracts.types.ts`; promotion runs as an ordered `bulkWrite` of two `updateOne` operations (demote all, then promote), so each operation is atomic per document but the batch is not — a reader may observe the intermediate state and a second-operation failure leaves the demotion committed, in `file:src/contexts/question/infrastructure/persistence/mongoose/repository/question.mongoose.repository.ts`.
- The 3-theme maximum is enforced by the domain policy at read-check time and by the schema `maxItems` validator on creation; the schema is not authoritative on updates (`file:docs/architecture.md` §5.5). Assignment and removal are unconditional single-document `$push`/`$pull` operations filtered by `_id` only, so two concurrent assignments or removals can break the 1–3 bound — a documented concurrency limitation tracked in #1271 (`docs/data-model.md`), not an atomic guarantee.

### Status transitions

- Creation status derives from the author role (see above). Archiving is the only status transition: `ArchiveQuestionUseCase` rejects an already-archived question (`QuestionAlreadyArchivedError`) and writes `status = archived` (`file:src/contexts/question/application/use-cases/archive-question/archive-question.use-case.ts`). There is no un-archive, activate or reject transition.

## Question-theme invariants

- Entity: `id`, `slug`, localized `label`/`aliases`/`description`, optional `color` (hex), `status`, timestamps (`file:src/contexts/question-theme/domain/types/question-theme.entities.ts`).
- Slug: kebab-case `SLUG_REGEX = /^[\da-z]+(?:-[\da-z]+)*$/u`, length `SLUG_MIN_LENGTH = 3` .. `SLUG_MAX_LENGTH = 50` (`file:src/shared/application/dto/zod/validators/string/constants/string.zod.validators.constants.ts`; wired in `file:src/contexts/question-theme/contracts/dto/zod/validators/question-theme/question-theme.dto.zod.validators.ts`).
- **Slug uniqueness is double-enforced**: `CreateQuestionThemeUseCase` and `ModifyQuestionThemeUseCase` check `findBySlug` first (`file:src/contexts/question-theme/application/use-cases/create-question-theme/create-question-theme.use-case.ts`, `file:src/contexts/question-theme/application/use-cases/modify-question-theme/modify-question-theme.use-case.ts`), and a unique Mongo index catches concurrent writes — duplicate key error code `MONGO_DUPLICATE_KEY_ERROR_CODE = 11000` is mapped to `QuestionThemeSlugAlreadyExistsError` (`file:src/contexts/question-theme/infrastructure/persistence/mongoose/repository/helpers/question-theme.mongoose.helpers.ts`, `file:src/shared/infrastructure/persistence/mongoose/constants/mongoose.constants.ts`).
- Statuses: `active` (default) and `archived` (`DEFAULT_QUESTION_THEME_STATUS`, `QUESTION_THEME_STATUS_ARCHIVED` in `file:src/contexts/question-theme/domain/constants/question-theme.constants.ts`). Creation status is fixed to the default by the contract type `status: typeof DEFAULT_QUESTION_THEME_STATUS` (`file:src/contexts/question-theme/domain/repositories/question-theme.repository-contracts.types.ts`) — clients cannot submit a status.
- Archive protection: `ArchiveQuestionThemeUseCase` refuses to archive a theme referenced by live (`pending` + `active`) questions, via the published `CountLiveQuestionsByThemeIdUseCase` and `ensureNoLiveQuestionsReferenceTheme` (`file:src/contexts/question-theme/application/use-cases/archive-question-theme/archive-question-theme.use-case.ts`, `file:src/contexts/question-theme/domain/rules/question-theme.rules.ts`). Live counting matches `status in [pending, active]` in `file:src/contexts/question/infrastructure/persistence/mongoose/repository/question.mongoose.repository.ts` (`countLiveByThemeId`); see also `file:docs/architecture.md` §5.4 (live vs active distinction).
- `label`, `aliases` and `description` are required localized values on creation (`file:src/contexts/question-theme/application/dto/question-theme-creation/question-theme-creation.dto.shape.ts`).

## Deduplication logic

- **Theme IDs in question creation**: unique via `areValuesUniqueByKey` refinement (see above).
- **Source URLs**: unique via `areValuesUniqueFromStrings` refinement (`file:src/contexts/question/application/dto/zod/validators/question.dto.zod.validators.ts`).
- **Applicable locales**: unique locale codes, max `LOCALES.length = 6` (`zQuestionApplicableLocales`, same file).
- **Filter arrays** (`categories`, `cognitiveDifficulties`, `ids`, `excludedIds`): unique via `zCreateFilterArray` (`file:src/shared/application/dto/zod/validators/array/array.zod.validators.ts`).
- **Theme slugs**: use-case pre-check + unique index + duplicate-key error mapping (see above).
- Duplicate theme assignment at runtime: blocked by the `findQuestionThemeAssignmentInQuestionByThemeId` check in the assign use case (see above).

## Error classes

One class per subdirectory under `domain/errors/` (`file:docs/architecture.md` §7.4). Question context (`file:src/contexts/question/domain/errors/`): `QuestionAlreadyArchivedError`, `QuestionCreationError`, `QuestionMaximumThemesError`, `QuestionMinimumThemesError`, `QuestionNotFoundError`, `QuestionPrimaryThemeAssignmentNotRemovableError`, `QuestionThemeAssignmentAbsentError`, `QuestionThemeAssignmentAlreadyExistsError`, `QuestionThemeAssignmentCreationError`, `QuestionThemeAssignmentModificationError`, `QuestionThemeAssignmentRemovalError`, `ReferencedQuestionThemeArchivedError`. Question-theme context (`file:src/contexts/question-theme/domain/errors/`): `QuestionThemeAlreadyArchivedError`, `QuestionThemeNotFoundError`, `QuestionThemeReferencedByLiveQuestionsError`, `QuestionThemeSlugAlreadyExistsError`.

`QuestionThemeNotFoundError` is the only published theme error a consumer may throw (`file:docs/architecture.md` §5.3). The four write/read-back errors (`QuestionCreationError`, `QuestionThemeAssignmentCreationError`, `QuestionThemeAssignmentModificationError`, `QuestionThemeAssignmentRemovalError`) intentionally map to HTTP 500 and are locked by tests (`file:docs/architecture.md` §7.4); all other classes are client-actionable and mapped by the `GlobalExceptionFilter` (`file:src/app/filters/global-exception/global-exception.filter.ts`).

## Known limitations

- **No answer-correctness model.** Answers are free text; the API neither defines nor validates "correct". The consuming game owns correctness (verified against `QuestionContent` and `question.rules.ts`).
- **No per-theme question cap.** The only theme/question count rule is the archive protection (a theme referenced by any live question cannot be archived); there is no maximum number of questions per theme anywhere in `question.constants.ts` or the domain rules.
- **Write-time enforcement differs per path.** The 3-theme maximum is read-checked on assignment and validated by Zod on creation; the "exactly one primary" rule is enforced by creation Zod and preserved by the demote/promote write pattern (there is no primary-count read-check). The Mongoose `themes` `minItems`/`maxItems` validators (`file:src/contexts/question/infrastructure/persistence/mongoose/schemas/question.mongoose.schema.ts`) do not run on update pipelines; `file:docs/architecture.md` §5.5 documents that the schema validator is not the authority on updates. Assignment and removal are single-document atomic writes; promotion is an ordered two-operation `bulkWrite` whose operations are individually atomic but whose batch is not, so a reader may observe the intermediate state. The `_id`-only filters mean concurrent operations can race both the 1–3 bound and the one-primary invariant (TOCTOU, tracked in #1271).
- **No un-archive / status transitions beyond archive.** Questions and themes can only move to `archived`; there is no activate or reject path in the domain rules (pending #1263 to confirm the product intent if needed).
- **Read-back failure is not idempotent.** A write can commit before the read-back fails, so the client may receive an error even though the mutation landed; a retry is a new mutation, and no idempotency-key mechanism exists. Revisit when idempotency keys or a transactional write path are introduced.
